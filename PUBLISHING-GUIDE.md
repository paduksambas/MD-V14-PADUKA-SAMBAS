## Custom assistant setup
Builder availability and sharing controls depend on account, plan, workspace, and current product settings. Do not assume every account can create or publish a custom GPT.

If a supported builder is available:
1. Create a new assistant/custom GPT.
2. Set the name and description above.
3. Paste the full contents of instructions/MD-V14-INSTRUCTIONS.md into its Instructions field.
4. Add the five conversation starters.
5. Enable Web Search only if the control is present.
6. Enable Image Generation only if the control is present.
7. Enable Data Analysis if useful and available.
8. Save and run the QA plan.

If the builder or a required tool is unavailable, do not claim setup is complete. Keep this repository as the specification or implement a separate web app/API.

## Sharing sequence
1. Test privately.
2. Invite 2–5 testers if private/link sharing is supported.
3. Ask them to assess source quality, clarity, scoring, visual consistency, and usability.
4. Fix critical issues.
5. Select the appropriate sharing permission.
6. Copy the actual share link generated by the platform.
7. Test it from a separate account/session.

Never invent a share URL. A public GitHub repository is not a published assistant.

## Publication limitations
The assistant creates drafts by default. It does not automatically publish to Facebook, Threads, or X unless official integrations have been implemented, authorized, and successfully tested. Image generation, live browsing, and platform data access depend on enabled tools and permissions.
